## 二、单条检测

### 2.1 功能说明

单条检测是最基本的检测功能，用于检测单个 HTTP 参数值是否包含攻击载荷。

### 2.2 操作步骤

1. **输入 Payload**
   - 在输入框中输入待检测的 HTTP 参数值
   - 示例：`' OR 1=1 --`

2. **选择模型**（可选）
   - **LightGBM**：传统机器学习模型，推理速度快
   - **TextCNN**：深度学习模型，准确率更高

3. **点击检测**
   - 点击"检测"按钮开始检测

4. **查看结果**
   - **攻击类型**：正常流量、SQL注入、XSS攻击、命令注入、路径穿越
   - **置信度**：模型对预测结果的置信程度（0-100%）
   - **概率分布**：各个类别的预测概率

### 2.3 结果说明

| 图标 | 类型 | 风险等级 | 说明 |
|------|------|----------|------|
| 🟢 | 正常流量 | 低 | 安全的 HTTP 参数 |
| 🔴 | SQL注入 | 高 | 可能的 SQL 注入攻击 |
| 🟠 | XSS攻击 | 高 | 可能的跨站脚本攻击 |
| 🟡 | 命令注入 | 高 | 可能的命令注入攻击 |
| 🟣 | 路径穿越 | 中 | 可能的路径穿越攻击 |

### 2.4 示例

**正常流量**
```
输入：hello world
结果：正常流量 (置信度: 99.99%)
```

**SQL 注入**
```
输入：' OR 1=1 --
结果：SQL注入 (置信度: 99.97%)
```

**XSS 攻击**
```
输入：<script>alert(1)</script>
结果：XSS攻击 (置信度: 99.98%)
```

## 三、批量检测

### 3.1 功能说明

批量检测支持同时检测多个 Payload，适用于大量数据的快速检测。

### 3.2 操作步骤

1. **输入 Payload**
   - **手动输入**：每行一个 Payload
   - **文件上传**：上传 txt 或 csv 文件

2. **选择模型**（可选）
   - 同单条检测

3. **开始检测**
   - 点击"批量检测"按钮

4. **查看结果**
   - **统计信息**：总数、攻击数、正常数、攻击率
   - **详细结果**：每个 Payload 的检测结果
   - **导出结果**：下载 CSV 文件

### 3.3 文件格式

**TXT 文件**
```
' OR 1=1 --
<script>alert(1)</script>
normal text
../../../etc/passwd
```

**CSV 文件**
```csv
payload
' OR 1=1 --
<script>alert(1)</script>
normal text
```

### 4.4 结果导出

检测完成后，可以点击"导出 CSV"按钮下载检测结果，包含以下字段：

| 字段 | 说明 |
|------|------|
| payload | 原始 Payload |
| label | 预测标签 |
| label_cn | 中文标签 |
| confidence | 置信度 |
| model | 使用的模型 |

## 四、HTTP 解析

### 4.1 功能说明

HTTP 解析功能支持解析 Burp Suite 格式的 HTTP 报文，自动提取所有参数并进行批量检测。

### 4.2 操作步骤

1. **粘贴 HTTP 报文**
   - 支持 Burp Suite 格式
   - 支持 GET/POST/Cookie/Header 参数

2. **点击解析**
   - 系统自动提取所有参数

3. **查看解析结果**
   - **参数列表**：提取的所有参数
   - **参数来源**：GET/POST/Cookie/Header

4. **批量检测**
   - 点击"批量检测"按钮
   - 查看检测结果

### 4.3 支持的格式

**GET 请求**
```
GET /search?q=test&id=1 HTTP/1.1
Host: example.com
```

**POST 请求**
```
POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded

username=admin&password=123456
```

**Cookie**
```
GET /dashboard HTTP/1.1
Host: example.com
Cookie: session=abc123; user=admin
```

### 4.4 参数提取规则

| 来源 | 提取规则 |
|------|----------|
| GET | URL 查询参数 |
| POST | 表单数据、JSON 数据 |
| Cookie | Cookie 键值对 |
| Header | 自定义 Header |

## 五、双模型对比

### 5.1 功能说明

双模型对比功能同时使用 LightGBM 和 TextCNN 两个模型进行检测，对比两个模型的预测结果。

### 5.2 操作步骤

1. **输入 Payload**
2. **点击对比**
3. **查看结果**
   - LightGBM 预测结果
   - TextCNN 预测结果
   - 是否一致

### 5.3 结果说明

- **一致**：两个模型预测结果相同，可信度更高
- **不一致**：两个模型预测结果不同，需要人工判断

## 六、AI 深度分析

### 6.1 功能说明

AI 深度分析功能接入大语言模型，对检测结果进行深度分析，提供攻击原理解析和防御建议。

### 6.2 操作步骤

1. **先进行检测**
   - 使用单条检测或批量检测功能

2. **点击 AI 分析**
   - 系统调用大语言模型进行分析

3. **查看分析结果**
   - **攻击原理**：详细解释攻击原理
   - **防御建议**：提供防御措施

### 6.3 支持的 AI 模型

| 模型 | 说明 | 配置 |
|------|------|------|
| LongCat | 默认模型 | 无需额外配置 |
| 豆包 | 字节跳动模型 | 需要 API Key |
| DeepSeek | 深度求索模型 | 需要 API Key |

### 6.4 分析示例

**输入**
```
' OR 1=1 --
```

**分析结果**
```markdown
## 攻击原理

这是一个典型的 SQL 注入攻击载荷。攻击者通过在参数值中插入 SQL 语句，
绕过身份验证或获取数据库中的敏感信息。

**攻击方式**：
1. `'` - 闭合原有的 SQL 引号
2. `OR 1=1` - 添加永真条件
3. `--` - 注释掉后续的 SQL 语句

**危害**：
- 绕过身份验证
- 获取敏感数据
- 修改或删除数据
- 执行系统命令

## 防御建议

1. **使用参数化查询**
   - 使用 PreparedStatement
   - 避免字符串拼接 SQL

2. **输入验证**
   - 验证输入格式
   - 过滤特殊字符

3. **最小权限原则**
   - 数据库用户使用最小权限
   - 禁用不必要的功能

4. **WAF 部署**
   - 部署 Web 应用防火墙
   - 配置 SQL 注入规则
```

## 九、常见问题

### Q1: 检测结果不准确怎么办？

**解决方案**：
1. 尝试使用另一个模型（LightGBM / TextCNN）
2. 使用"双模型对比"功能
3. 使用"AI 深度分析"功能获取更多信息

### Q2: 批量检测有数量限制吗？

**回答**：
是的，单次批量检测最多支持 500 条 Payload。如果需要检测更多数据，可以分批进行。

### Q3: 如何导出检测结果？

**回答**：
在批量检测结果页面，点击"导出 CSV"按钮即可下载检测结果。

### Q4: 历史记录能保存多久？

**回答**：
历史记录默认永久保存在 SQLite 数据库中。如果需要清理，可以手动删除或清空记录。

### Q5: AI 分析功能需要付费吗？

**回答**：
默认使用 LongCat 模型，无需付费。如果需要使用其他模型（如豆包、DeepSeek），需要配置相应的 API Key。

### Q6: 如何提高检测准确率？

**建议**：
1. 提供完整的 Payload（不要截断）
2. 使用"双模型对比"功能
3. 结合"AI 深度分析"功能进行判断

### Q7: 系统支持哪些攻击类型？

**回答**：
系统支持 5 种分类：
- 正常流量（norm）
- SQL 注入（sqli）
- XSS 攻击（xss）
- 命令注入（cmdi）
- 路径穿越（path-traversal）

### Q8: 如何部署自己的实例？

**回答**：
请参考 [部署文档](部署文档.md)，包含详细的部署步骤。
